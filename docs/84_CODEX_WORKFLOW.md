# 84 — Codex Workflow

## How Codex should work

1. Read relevant docs.
2. State plan.
3. Implement minimal scope.
4. Run tests/checks.
5. Fix errors.
6. Update docs/changelog.
7. Report summary.
8. Stop.

## Codex must not

- Start another phase automatically.
- Add unrelated features.
- Skip tests.
- Hide errors.
- Commit secrets.
- Remove approval gates.

## Reporting format

```text
Completed:
Changed files:
Commands:
Tests:
Known issues:
Next:
```
